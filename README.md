# doyoursecurityplus

A CompTIA Security+ SY0-701 drill portal that retargets itself at your specific
errors. Not a flashcard deck with a Security+ skin.

```bash
python3 serve.py                # run it now, on http://localhost:8777
./scripts/service.sh install    # macOS or Linux: run it always, from login onward
```

No build step, no npm, no dependencies. Plain ES modules and JSON, served by
one Python file. The rules the code is held to are in `CONVENTIONS.md`, and
`bin/check` is the one command that enforces them.

## The idea

Anki schedules a card. Fail it and the same card returns, so you eventually
memorise the card rather than the concept. This schedules the **misconception**.

Every wrong answer option in the bank is labelled with the specific wrong belief
that leads to it. Pick it, and the app records "confused WPA3-SAE with
WPA3-Enterprise", not "missed question 412". That belief is banked with a
targeted correction, and when it comes due the queue serves **a different
question** that tests the same distinction. Two clean passes on two different
questions retires it. You cannot retire a misconception by memorising the
question that exposed it.

```
wrong answer -> distractor names the misconception
             -> mentor correction shown immediately, and banked
             -> comes back in ~8 minutes, on a DIFFERENT question
             -> 2 clean passes on distinct questions = retired
```

When you keep missing it, the response escalates rather than repeating:

| Miss | What happens |
|---|---|
| 1st | The full correction: diagnosis, contrast table, rule of thumb |
| 2nd | Same card, flagged as a repeat, leading with the rule |
| 3rd+ | It stops explaining. A **contrast drill**: two questions on the same distinction whose correct answers differ |

Three more things the mentor watches. Mark a question as a guess (`G`) and a
right answer is scored but never counts toward clearing anything, while a
confident miss escalates faster than an admitted one. A wrong answer in under
six seconds on a hard question is flagged as rushed. And authored prerequisite
edges let the queue route **backward**: when a correction sits on top of one
that is still open, you get the one underneath first, and the card says why.

The mentor is a lookup table keyed to the wrong belief, plus a scheduler. It
writes nothing on the fly. Every correction was written in advance and
reviewed, because an exam tool that invents security explanations would be
confidently wrong some of the time, with no way to tell which time.

## How it is built

### Data model

```
Objective (28)  ->  Topic (684)  ->  Item (MCQ | PBQ)
                                           |
                                      Distractor -> Misconception -> Mentor card
```

Three content shapes, all plain JSON under `content/`, one file per objective
for items and misconceptions, one file per PBQ. `scripts/format_content.py`
writes every record in one canonical shape: fixed key order, defaults left
out, one option or contrast row per line.

A **misconception** is the scheduled object: what you actually got wrong,
independent of which item exposed it.

```jsonc
{
  "id": "wpa3-sae-vs-enterprise",
  "label": "WPA3-Personal (SAE) vs WPA3-Enterprise (802.1X)",
  "objective": "4.1",
  "topics": ["wi-fi-protected-access-3", "aaa-radius"],
  "severity": "high",              // high | medium | low: exam impact
  "mentor": {
    "diagnosis": "What you probably believed when you picked the distractor.",
    "contrast": [["Aspect", "WPA3-Personal", "WPA3-Enterprise"],
                 ["Credential", "One shared passphrase", "Per user, from the identity store"]],
    "rule": "One short rule of thumb you can recall under time pressure.",
    "tell": "The words in the question stem that should trigger this rule.",
    "trap": "Why the wrong answer looked right."
  },
  "retireAfter": 3                 // clean passes on DISTINCT items; 2 is the default and left out
}
```

An **item** is single or multiple select. Every wrong option names a
misconception; an option without one is wasted teaching surface and the
validator rejects it.

```jsonc
{
  "id": "sec-4.1-012", "type": "mcq", "objective": "4.1",
  "topics": ["wi-fi-protected-access-3"], "difficulty": 3,
  "stem": "The question text.",
  "options": [
    {"id": "a", "text": "...", "correct": true, "why": "Why this is right."},
    {"id": "b", "text": "...", "misconception": "wpa3-sae-vs-enterprise",
     "why": "A correction aimed at THIS error, not a restatement of the answer."}
  ]
  // "selectCount": 2 on an "mcq-multi"; a correct option may carry
  // "missedMisconception" for the error of leaving it out
}
```

A **PBQ** declares its interactive surface, its solution, and subtasks that
score independently, each mapped to a misconception, so a half-right PBQ still
produces precise remediation for the half you missed.

```jsonc
{
  "id": "pbq-wireless-001", "kind": "wireless-config",   // acl-table | network-diagram | drag-order
  "objective": "4.1", "topics": [...], "difficulty": 4,
  "title": "Shown in the lab list", "scenario": "The requirements, written like the exam.",
  "targetSeconds": 480,
  "config": { ... },      // the surface
  "solution": { ... },    // what correct looks like; must score full marks
  "subtasks": [{ "id": "st1", "label": "Authentication mode", "points": 2,
                 "misconception": "wpa3-sae-vs-enterprise" }]
}
```

Vocabulary comes in two more forms. Imported recall cards (`items/recall.json`)
are term and definition, revealed and self-graded, kept to a small share of a
session because the exam never asks you to reveal anything. Derived questions
(`items/derived.json`) turn a card into "which term is being described" with
the sibling terms as distractors, and bank the authored misconception for that
pair where one exists. `content/glossary.json` is CompTIA's acronym list,
expanded inline wherever an acronym appears in a stem or an option.

### The PBQ engines

One harness, four graders, in `app/grade.js`.

**`acl-table`** executes your rule set: synthetic packets go through it top to
bottom, first match wins, implicit deny at the end. It catches the rule set
that works but is too broad, the rule shadowed by a broader one above it, and
the service port on the wrong side. The policy is also printed as plain text
under the grid, the way a device would show it.

**`wireless-config`** grades each field on its own, with dependency awareness:
choosing Personal mode makes the RADIUS fields unreachable rather than wrong.

**`network-diagram`** is a clickable topology with per-host evidence. Clicking
a host reads its evidence; marking it compromised is a separate act. Every one
mixes compromised hosts with hosts that merely show the effects, and a wrong
host costs half what a right one earns.

**`drag-order`** is click to place, not HTML5 drag: it works with a keyboard
and on touch, and positions fill in any order. Sequences score per position and
also report how many consecutive pairs held.

The count is deliberate and it stops where it is. A PBQ earns its place when it
trains an operation multiple choice cannot: building a rule set and reading it
back, ordering steps where the order is the answer, gathering evidence before
deciding. Where the discrimination is "which term is this", a PBQ is a slower
multiple choice question.

### Study modes

- **Drill** blends due corrections, items due for review, and new coverage
  weighted toward whichever domain is furthest under its exam weight.
- **Weak spots** serves only banked corrections that are due.
- **PBQ lab** runs the performance-based questions against an 8 minute target.
- **Mock exam** is format faithful: PBQs first, no feedback until you submit, a
  clock that does not stop, flag and review, and a scaled 100 to 900 estimate.
  A mock answer updates the item's own schedule, as a drill answer would.
- **Mentor bank** is every correction you have collected, with its progress.
- **Readiness** leads with where to spend the next session and a per-objective
  heatmap, then the estimated score band against the 750 pass line, confidence
  calibration, and domain balance.

### Readiness, and its two denominators

Per-objective mastery is accuracy on graded practice, weighted by item
difficulty, dragged by open misconceptions, folded with the best PBQ score,
rolled up by exam weight. It is reported as a band, not a number, because a
small sample over a 100 to 900 scale cannot support false precision.

Two denominators are kept apart on purpose. **Coverage** is `itemsSeen /
min(itemsAvailable, 12)`: twelve is the sample worth having, and an objective
that cannot supply twelve is scored out of what it has. This measures you.
**Bank depth** is the share of an objective's blueprint topics that any graded
item reaches. This measures the content, and it is a "thin" flag, never folded
into mastery. Mixing them reports a thin bank as a weak learner.

## Where your progress lives

The misconception bank is the value of the tool, so it is kept in two tiers and
two resources.

| Resource | Fast tier | Durable tier |
|---|---|---|
| State document: what you know, what you got wrong, when you studied | `localStorage` | `~/.doyoursecurityplus/state.json`, every write snapshotted, last 40 kept |
| Review log: one row per answer, append only | an outbox in `localStorage` | `~/.doyoursecurityplus/reviews.jsonl` |

The state document never grows per answer; it grows with the bank. Reviews,
PBQ attempts and mock results are rows in the log, which the app reads back
only for the recent window: today's count, a month of calibration, the mock
history.

The server exposes exactly these as resources: `GET` and `PUT /api/state`,
`GET` and `POST /api/reviews`, `GET /api/content` (the whole bank in one
gzipped response, rebuilt when a file changes and answered with `304` when the
browser already holds it, so a new file needs no manifest and a boot is one
request for content), `GET /api/health` (what Settings shows). A `PUT`
is a conditional replace: it carries `If-Match` with the version it was built
on, and the server answers `412` with its newer copy if another session has
saved since, which the sidebar reports rather than silently picking a side.
Resolving the conflict in this browser's favour is an unconditional replace.

On start-up the newer copy wins. Settings shows the file path and what is on
disk. Open the app with `?scratch=1` to test it without touching your
progress: separate keys, no server writes, and a banner saying so.

`python3 scripts/backup.py backup` writes a dated tarball of the state
document, the log and the snapshots to `~/.doyoursecurityplus-backups`, and
`python3 scripts/backup.py restore FILE` puts one back after a typed yes and a
safety backup of what is there. A restore is a new write: the restored
document gets a fresh `updatedAt`, so a tab that still holds the copy it
replaced takes the restored one on reload instead of pushing the old data
back, and a tab that is not reloaded is refused on its next save.

`./scripts/service.sh install` runs the server as a per-user service, a
**launchd agent on macOS** or a **systemd user unit on Linux**, so the port,
and therefore the browser origin, never changes; `--remind 18:30` adds a daily
notification (osascript on macOS, notify-send on Linux) that reads the log and
stays quiet once you have hit your goal. A Linux user unit stops when you log
out unless you run `loginctl enable-linger $USER`, which the script leaves to
you. Either way the server writes `logs/server.log` itself and rotates it at 1 MB with three
old files kept, so the logs can never pass about 4 MB, and a port already in
use is a quiet wait rather than a crash loop.

## Pacing

FSRS (stability, difficulty, retrievability) with short relearning steps on
top, so a correction you made 30 seconds ago does not wait a day. **Set your
exam date**: the drill screen asks for it until you do. A correction is
always retested before it. An item whose next review would fall after it is
left alone, because FSRS only lets an interval run until recall falls to your
target, so it is still above target on the day. The drill screen states the
daily load the date implies and says so when your pace cannot carry it.
Pace profiles: `bootcamp` (default), `balanced`, `longhaul`.

## Your own materials

`content/index/` holds page indexes for study guides you own: section titles
and page numbers only, nothing copied. A mentor card points at the page in the
book already on your shelf. Build one with `scripts/build_reference_index.py`.

## Adding content

Items and misconceptions live in one file per objective (`content/items/4.1.json`,
`content/mentor/4.1.json`); PBQs are one file each under `content/pbq`. The
server lists the directory, so there is nothing to register. After an edit:

```bash
python3 scripts/format_content.py && bin/check
```

`bin/check` runs, in order: the canonical shape, the content validator
(structure and reference integrity: every distractor names a misconception that
exists, every misconception has enough distinct items to be retired, every
objective has graded material), the repository shape, the state shape, the
materials, the README counts, and the self test headless in the Chrome on this
machine. The self test page runs every PBQ's reference answer through the real
graders, exercises the misconception loop end to end, asserts every blueprint
topic is reached, checks every action in the templates has a handler, and
builds queues under a seeded random: a contrast pair stays adjacent and in
order, an open prerequisite is routed to first, no review lands past the exam
date, and vocabulary gets its floor and never more than its cap. The
headless runner then drives the real `serve.py` and the real app through the
persistence story, each scenario on its own throwaway data directory: a stale
save refused with 412 over HTTP and through the client, a corrupt `state.json`
read from its snapshot, an outbox replayed after the server was down, and a
pre-resource document absorbed into the log. It then walks all twelve
screens under four conditions, the server down, an empty log, a PBQ whose
kind has no engine, and a bank too small for a mock block, and fails on a
missing heading, a blank panel or anything thrown. Last, it presses real
keys and reads Chrome's accessibility tree: focus survives every render,
every control under main has a name, and a state change is announced. The
stress scenario abuses the real app and server: Enter mashed on a submitted
question and a PBQ, a mock submitted twice in one frame, a chip held across a
resize to 375 px, eight ACL rules cycled at full speed and Tab-looped, the exam
date set and cleared and set, and the server killed for twelve answers; no
error, no duplicate or lost row, focus on a control. The latency scenario
times every repeated action on a heavy record with the CPU slowed fourfold. It refuses to run against
any server that does not report a throwaway directory. Without Chrome the page is
manual: open http://localhost:8777/selftest.html, which also lists the by-hand
checks from the interface skill.

```
scripts/

  build_glossary.py          regenerate the acronym glossary from the same document
  format_content.py          one canonical shape for every item and mentor file (--check)
  validate_content.py        structure and reference integrity
  check_shape.py             no build step, imports, exports, classes, origin, nouns, one implementation
  check_state_shape.py       the state document never grows per answer
  check_materials.py         no shadow, gradient or blur; every colour a token
  check_docs.py              README counts come from the content (--write)
  backup.py                  dated tarball of the study data, and a confirmed restore
  capped-log.sh              keeps launchd's crash.log under 256 KB on every launch
  replay.py, replay.js        the real log through the real scheduler, on a copy: what was wasted
  selftest.py                selftest.html plus the persistence scenarios, headless, non-zero exit on failure
  derive_mcq.py              recall cards -> discrimination questions (--retag)
  import_anki.py             .apkg -> tagged recall items
  build_reference_index.py   study guide PDF -> page index (titles only)
  service.sh                 launchd (macOS) or systemd (Linux): install, status, logs, reminder, hooks
```

## Content integrity

Every item is original, written against the published objective. Nothing is
transcribed from a live exam or a commercial question bank; CompTIA treats
verbatim exam content as grounds for revoking a certification, and a bank built
that way would teach the questions rather than the material. `reference/` holds
CompTIA's own objectives document, free and public, kept for personal study and
not for redistribution.

## Known gaps

- The bank leans over on domain 4 and under on domain 2. Mocks draw by exam
  weight regardless, and the drill routes by what you have seen, so little of
  this reaches you.
- Scaled scores are an estimate. CompTIA's weighting model is confidential.
- The imported deck is third-party and its definitions have never been
  reviewed. Treat derived questions as drilling, your own notes as the authority.
